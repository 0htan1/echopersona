# EchoPersona 使用说明

面向最终用户的操作手册。如果你是部署者，先看 [DEPLOY.md](./DEPLOY.md)。

---

## 这是什么

EchoPersona 把一段真实的聊天记录，还原成一个**可以持续对话的 AI 人格**，并且能用你自己的语音合成服务让它「说话」。

它做四件事：

1. 读取你上传的聊天记录（你本人有权使用的那些）
2. 分析其中**对方**的说话方式、性格倾向、你们之间的共同记忆
3. 生成一个可对话的人格，聊天时会自然引用那些记忆
4. 调你自己的 BreezeTTS 服务，把回复变成语音

**它不做什么**：它不会伪装成真人。每一次对话，界面都会标明这是 AI 模拟，回复里的「记忆」来自你上传的记录，不是它真的记得。

## 一、注册与登录

打开站点，点「开始使用」注册。需要：

- 邮箱（登录用）
- 密码（至少 8 位，要同时含字母和数字）
- 勾选同意隐私说明与使用条款 —— 这一步必须勾，否则不允许注册

注册后自动登录。登录态默认保持 30 天，关掉浏览器再打开不用重新登录。

忘记了密码：登录页点「忘记密码」，输入邮箱。如果站点配置了邮件服务，你会收到重置链接；
如果没有配置，链接会打印在服务器日志里，需要联系站点管理员获取。

---

## 二、配置你自己的 API Key（必须先做）

EchoPersona **不自带任何模型额度**。你需要填自己的 Key，否则聊天和语音都用不了。

进入「设置 → 密钥配置」。

### 2.1 配置 LLM（文本模型）

点「新增配置」，填：

| 字段 | 说明 |
|---|---|
| 配置名称 | 随便起，比如「DeepSeek 主力」 |
| 接口地址 | OpenAI 兼容的 base URL，如 `https://api.deepseek.com/v1` |
| API Key | 你的 Key |
| 模型名称 | 如 `deepseek-chat` |
| 是否默认 | 第一个配置会自动成为默认 |

保存后点「测试连接」。能列出模型列表就说明通了。再点「测试对话」，确认能真的返回一句话。

> **关于保存 Key**：默认勾选「加密保存」，Key 会用 AES-256-GCM 加密后存进数据库，页面上只显示前 3 位和后 4 位。
> 如果你不想留下痕迹，取消勾选 —— 这时 Key 只存在服务器内存里，服务重启就要重填。

**可选：向量检索用的 embedding 模型**

如果你配了 embedding 模型（比如 `text-embedding-3-small`），长期记忆会用「关键词 + 向量」双路召回，找得更准。
不配也能用，只是退化成纯关键词检索，仍然可正常工作。

### 2.2 配置 BreezeTTS（语音）

点「新增配置」：

| 字段 | 说明 |
|---|---|
| 配置名称 | 如「我的 Breeze」 |
| 服务地址 | 托管版填 `https://api.breezeblue.ai`；自建填你的地址，如 `http://127.0.0.1:9000` |
| 接口类型 | 不确定就选「自动识别」，系统会去探测 |
| API Key | 托管版必填；自建通常不需要 |

两种服务形态的区别：

- **Breeze Blue 托管版**：先「克隆音色」得到一个 `voice_id`，之后每次合成都用这个音色
- **自建 breeze-tts-2**：不需要预先克隆，每次请求都上传参考音频 + 参考文本

点「测试」确认连通。

### 2.3 上传参考音频

语音页面「参考声音」区域，上传一段**你有权使用**的音频（支持 mp3 / wav / m4a / ogg，10 MB 以内）。

必填项：
- 参考文本：音频里说的那段话的文字。这段文字会影响合成效果，尽量准确。
- 授权确认：必须勾选。你确认对该音频拥有合法使用权。

托管版还会多一步「克隆到 Breeze」，把音频上传到远端生成音色，返回的 `voice_id` 会自动保存。

> **法律提醒**：未经许可克隆他人声音可能侵犯人格权，在部分地区还涉及违法。请只使用你本人或已获明确授权的音频。

## 三、创建人格

「人格」页 → 「新建人格」，填：

- **名称**：被复刻那个人在你心里的称呼
- **关系**：如「多年好友」「大学室友」
- **描述**：你希望 AI 记住的补充背景，会作为分析时的参考
- **语言**：中文 / 英文
- **相似度模式**：
  - **自由** —— 只学语气，具体说什么由模型发挥，适合日常闲聊
  - **自然** —— 兼顾语气和内容习惯（推荐默认）
  - **高仿** —— 尽量贴近原说话长度和用词，适合想还原特定感觉时

建好后进入人格详情。

---

## 四、上传聊天记录

人格详情 → 「聊天记录」标签。

### 支持的文件

| 格式 | 说明 |
|---|---|
| `.txt` | 微信/QQ 导出的纯文本，或「时间 说话人」换行分隔的对话 |
| `.json` | 消息数组，或带 `messages`/`data` 字段的嵌套结构；兼容中英文字段名 |
| `.csv` | 带表头，自动识别逗号/分号/制表符分隔；支持引号内换行 |
| `.md` | Markdown 里用粗体标注说话人，或标题式分段 |
| `.zip` | 以上格式打包上传，会安全解压（防路径穿越、防解压炸弹） |

单个文件最大 50 MB。可以一次拖多个。

**不支持的格式**：微信的 `.db` / `.dat` 加密数据库、WhatsApp 加密备份、Telegram 的 `.json` 导出版本差异较大。
遇到这些，页面上会明确告诉你不支持以及替代方案，不会假装解析成功。

### 上传流程

1. 拖入文件，列表里会显示待上传项
2. 点「解析预览」，先看前几条解析结果对不对
3. 确认没问题再点「导入」

导入时会自动去重（同样内容不会重复进库），并给出「新增 X 条 / 重复 Y 条」的反馈。

### 必须做的一步：指定要复刻谁

系统会列出记录里出现的所有说话人，并统计各自发言条数。你需要点一下**哪个是「被复刻的人」**。

判断错了整个分析就跑偏了，所以这一步务必确认。点错了可以随时改，改完会重新建立索引。

导入错了：在导入记录里点删除，可以连带删掉那批消息。

## 五、分析人格

「分析」标签 → 点「开始分析」。

分析是后台任务，页面会显示进度。它会做三件事：

1. 统计语言特征：平均句长、短句比例、表情符号使用率、口头禅、标点习惯、主动发起话题的频率
2. 用 LLM 归纳性格倾向和关系记忆，每一条结论都带置信度
3. 把聊天记录切块、建索引，为后续的长期记忆检索做准备

有记录越多分析越准。几十条就能跑，几千条效果明显更好。

### 关于性格结论的免责说明

页面上所有性格描述都会标明：**这是基于文本的推断，不构成心理诊断**。

它说的是「这段对话里体现出的表达习惯」，不是「这个人本质上是什么样」。同一人在不同关系、不同时期的表现可能完全不同。

### 手动修正

「画像」标签里可以直接改分析结果：
- 补充它漏掉的口头禅
- 删掉明显不对的判断
- 调整某条记忆的重要程度

改完保存即可，下次对话就会按修改后的版本走。

### 增量分析

后来补传了新记录，再点一次「开始分析」即可。旧的分析结果会保留为历史版本，新版本生效，不会丢东西。

## 六、长期记忆

「记忆」标签里是 AI 记住的所有事。

每条记忆有：
- **类型**：事件 / 偏好 / 事实 / 约定 / 共同话题
- **重要度**：1–5 颗点，越高越容易被想起来
- **置信度**：这条结论有多可靠
- **来源**：从哪段对话里提取出来的

你可以：
- 搜索（支持中文分词）
- 筛选类型
- 手动新增（比如「她讨厌别人说随便」这种记录里没直说但你确定的事）
- 编辑、删除

**重要度怎么用**：聊天时不是把所有记忆都塞给模型，而是按「和当前话题的相关度 × 重要度 × 时间新鲜度」排序，只取最相关的几条。所以把重要的事标成 5 颗点，它会更容易被想起来。

## 七、聊天

点人格卡片进入对话。左侧可以切换人格和会话。

### 基本操作

| 操作 | 说明 |
|---|---|
| 发送 | Enter 发送，Shift+Enter 换行 |
| 停止 | 生成中点「停止」，已生成的部分会保留 |
| 重新生成 | 对最后一条回复不满意，点「重来」 |
| 编辑 | 自己的消息可以改，改完可以重新生成回复 |
| 删除 | 任何消息都能删 |
| 切换模式 | 顶部可随时切换 自由 / 自然 / 高仿 |

回复是逐字流式输出的，不是等全部生成完才出现。

### 它会承认自己不知道

这是刻意设计的。如果你问「2019 年 3 月 5 号你在干嘛」，而记录里没有，它会说「这个我不记得了」，而不是编一个答案。

**它不会伪造真实人物的经历**。如果对话里出现明显超出记录范围的「回忆」，那是模型的发挥，请以记录为准。

### 记忆是怎么被用上的

每轮对话，系统会：
1. 拿你的话去检索相关记忆和原始对话片段
2. 按相关度排序，取最相关的几条（有长度上限，不会把全部历史塞进去）
3. 拼进提示词，并明确要求「不要照搬记忆原文，要像自然想起那样说出来」

回复上方有时会出现一个小的记忆标记，表示这轮用到了历史记忆。鼠标悬停可以看到用了几条。

## 八、语音

### 生成语音

每条 AI 回复下方有播放按钮。点一下开始生成 + 播放。

- 自动播放：设置里可以打开，之后每条回复生成完自动出声
- 下载：生成后可以下载音频文件
- 重新生成：对这次效果不满意，点重试
- 调速：0.5x – 2.0x

相同文本 + 相同音色 + 相同参数会命中缓存，不会重复消耗你的 TTS 额度。

### 语音页面

「语音」页里是历史生成记录，可以批量试听、下载、删除。参考声音也在这里管理（设为默认、删除）。

## 九、账号与数据

「设置 → 账号」里可以：

- 改昵称、头像
- 改密码（需要输入当前密码）
- 改邮箱（需要输入当前密码验证）
- 查看所有登录中的设备，可一键退出其他设备
- **导出全部数据**：下载一个 JSON，包含你的人格、消息、记忆、画像。
  出于安全考虑，API Key 不会导出（导出的是占位符）
- **删除账号**：需要输入 `DELETE` 并确认密码

### 删除账号会发生什么

立即且不可恢复地删除：
- 账号本身
- 所有人格、会话、消息
- 所有记忆和索引
- 上传的原始文件、生成的音频、头像
- 所有 API Key 配置

数据库里只保留一条匿名化的记录（邮箱变成 `deleted+随机串@invalid.local`），用于维持外键完整性。

如果你只是想清空某个人格的数据但保留账号，用人格详情页底部的「危险操作」区域。

## 十、隐私与安全

### 你的数据去哪了

- 聊天记录、人格、记忆：存在你自己的站点数据库里，不外传
- 调用 LLM 时，会把**当轮对话上下文 + 检索到的相关记忆**发给**你自己配置的** API 服务商
- 调用 TTS 时，会把**要朗读的文本 + 参考音频**发给**你自己配置的** TTS 服务
- 平台不向任何第三方转发你的数据，也没有内置的数据回传

### API Key 怎么存的

- 选「加密保存」：AES-256-GCM 加密后入库，密钥由服务器的 `MASTER_KEY` 派生
- 不选：只存内存，重启失效
- 任何接口都不会返回完整 Key，前端只能看到 `前3位****后4位`
- 日志里会对敏感字段做脱敏

### 管理员能看到什么

管理员可以看到：用户数量、注册时间、存储占用、任务状态、错误日志、资源使用。

管理员**看不到**：你的聊天内容、你的人格画像、你的 API Key。

这是接口层面就做了限制 —— 管理后台的查询语句里根本不包含消息内容字段。

## 十一、常见问题

**上传后分析出来的性格完全不对**
八成是「要复刻谁」选错了。去「聊天记录」标签重新指定说话人，再分析一次。

**对话时它完全不提以前的事**
检查「记忆」标签里有没有内容。没有的话先跑一次分析。有内容但没被用到，可能是那条记忆重要度太低，标成 5 颗点试试。

**语音生成失败**
1. 看「设置 → 密钥配置」里 TTS 的「测试」是否通过
2. 托管版检查是否已克隆出音色（需要一个 `voice_id`）
3. 自建版检查是否上传了参考音频和参考文本
4. 自建服务在 127.0.0.1 时，需要部署者设置 `SSRF_ALLOW_PRIVATE=1`

**提示「请求过于频繁」**
登录、注册、发消息都有频率限制（防暴力破解和滥用）。等几分钟再试。

**换设备后要重新登录**
登录态绑定在浏览器的 Cookie 上。如果之前的会话被「退出其他设备」清掉了，重新登录即可。

## 十二、使用边界

这个工具是用来**留存和回忆**的，不是用来替代真实关系的。

请遵守：

- 只上传你有权使用的聊天记录
- 只克隆你本人或已获明确授权的语音
- 不要用它冒充他人身份与他人交流
- 不要用它生成骚扰、欺诈、伪造证据类内容

平台上每个人格都会明确标注「AI 模拟」，这是不会去掉的。
